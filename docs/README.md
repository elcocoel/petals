# Editing the documentation

`apps/web/app/(site)/docs/[[...slug]]/page.tsx` statically renders these pages within the site. The eleven section folders set the navigation, in the order their `index.md` gives. Each `index.md` has YAML frontmatter: `title`, `order`, and optional `include` and `exclude`. Includes name canonical repository files, folders (ending in `/`), or filename patterns with `*`. Exclusions match basenames. Chapters use their own title and brain status. Add a chapter or recipe in an included folder and the next build discovers it.

The source files stay in `brain/`, `specs/`, and `packages/core/schema/`. Do not copy them here. The schema registry supplies each format's current version, including the separate definitions in `flower.schema.json`; `pins.json` selects its real fixtures. Nested fields resolve local JSON Schema references. Full schemas remain visible alongside the field tables. The view vocabulary reads core's definitions and the site's default person view.

Agent commands keep the placeholders in their source, and the docs show them as written; the site fills in its address when it serves them to an agent (`/skill.md`, `/setup`).

Markdown uses remark, GFM and rehype. Heading anchors and the contents list come from the same rendered tree. Relative links to rendered files stay within docs; other repository links open GitHub. Raw HTML and unsafe URL schemes are discarded. There is no MDX execution or runtime filesystem requirement: all routes, including `/docs`, are generated by `next build`. Source edits require a rebuild, just like code changes. Unknown routes return 404.

After loading Node 24, run from the repository root:

```sh
node --test apps/web/components/docs/content.test.ts
bash scripts/check.sh
```

The docs tests cover canonical sources, schema examples, nested fields, current dimensions, GFM, anchors and unsafe links. The full check also runs the production build. Mobile navigation is a route-local component; it is not part of the shared UI lab.

## Guides and system reference

Section child Markdown files are discovered automatically and sorted by frontmatter `order`. Canonical includes stay system reference; the root `README.md` is included directly as a guide, never copied. The site labels and styles the two kinds separately, including separate navigation groups.

Put local raster illustrations in `docs/assets/`, with lowercase hyphenated PNG or WebP names and provenance in that folder's README. Link to them relatively from a guide. The static asset route serves only the enumerated files; unknown names return 404, and remote images stay text. Rebuild after adding assets.
